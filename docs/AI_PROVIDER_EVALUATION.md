## 2. المضيف والمنفذ الافتراضيان

**الخلاصة المُتحققة من الشيفرة:**

- في `envconfig/config.go` الدالتان `Host()` و`ConnectableHost()`:
  - المتغير `OLLAMA_HOST` هو المتحكّم الوحيد بالمضيف والمنفذ.
  - القيمة الافتراضية عند عدم ضبط `OLLAMA_HOST` هي **`http://127.0.0.1:11434`** (المخطط `http` والمنفذ `11434`). هذا مثبت حرفيًا في التعليق `Default is scheme "http" and host "127.0.0.1:11434"` وفي الخريطة التوضيحية في نهاية `config.go`: `IP Address for the ollama server (default 127.0.0.1:11434)`.
  - إذا كانت القيمة بلا مخطط (`host:port` فقط) يُفترض `http`.
  - إذا كانت القيمة `ollama.com` وحدها يُوسّع إلى `https://ollama.com:443`.
  - عند استخدام `0.0.0.0` أو `::` للربط (binding)، تحوّلها `ConnectableHost()` إلى `127.0.0.1` أو `::1` للاتصال كعميل (مهم على Windows).
  - المنفذ غير الرقمي أو خارج `[0, 65535]` يُعاد إلى المنفذ الافتراضي مع تحذير `slog.Warn`.
- في `README.md` و`docs/api.md` و`docs/openapi.yaml` جميع الأمثلة تستخدم `http://localhost:11434` كخادم `servers[0].url`. هذا مطابق لمنطق `Host()` لأن `localhost` و`127.0.0.1` كلاهما ضمن `AllowedOrigins` افتراضيًا.

**متغيرات بيئة موثقة في `envconfig/config.go`:**

| المتغير | الافتراضي | الوصف المُتحقق |
| --- | --- | --- |
| `OLLAMA_HOST` | `127.0.0.1:11434` مع `http` | عنوان خادم Ollama |
| `OLLAMA_ORIGINS` | قائمة مبنية تضم `localhost`, `127.0.0.1`, `0.0.0.0`, `app://*`, `file://*`, `tauri://*`, `vscode-*` | أصول CORS المسموحة |
| `OLLAMA_MODELS` | `$HOME/.ollama/models` (عبر `os.UserHomeDir()`) | مسار تخزين النماذج |
| `OLLAMA_KEEP_ALIVE` | `5m` | مدة بقاء النموذج محمّلًا في الذاكرة بعد آخر طلب |
| `OLLAMA_LOAD_TIMEOUT` | `5m` | مهلة اكتشاف توقف تحميل النموذج (0 أو سالب = بلا نهاية) |
| `OLLAMA_NUM_PARALLEL` | `0` (يختار الخلفية قيمته) | حد الطلبات المتوازية |
| `OLLAMA_MAX_LOADED_MODELS` | `0` (يختار الخلفية) | حد النماذج المحمّلة في GPU |
| `OLLAMA_MAX_QUEUE` | `512` | حد الطلبات المنتظرة في الطابور |
| `OLLAMA_MAX_TRANSFER_STREAMS` | `4` | حد تيارات النقل المتوازية لنماذج safetensors |

## 3. اكتشاف الخادم المحلي (طريقة مُقترحة وموثّقة)

**لا تعتمد على وجود المنفذ مفتوحًا فقط؛ نفّذ فحص صحّة تطبيقيًا (application-level health check):**

1. **بناء عنوان الأساس:** اقرأ `OLLAMA_HOST` إن وُجد، وإلا استخدم `http://127.0.0.1:11434`. تجنّب افتراض `localhost` وحده؛ احترم القيمة المضبوطة من المستخدم لأنها قد تكون `http://0.0.0.0:11434` أو منفذًا مخصصًا أو `https://…`.
2. **فحص سريع غير مكلف:** `GET /api/version` — يُرجع `{"version": "0.40.18"}` (مثال) ولا يحتاج نموذجًا محمّلًا. النجاح يعني الخادم حيّ وقابل للاتصال.
3. **فحص بديل:** `GET /api/tags` — يُرجع قائمة النماذج المحلية. يُستخدم أيضًا لمعرفة هل يوجد أي نموذج مثبت أصلًا. يعمل حتى بلا نماذج (يُرجع `{"models": []}`).
4. **المهلات المقترحة للاكتشاف:**
   - مهلة اتصال (connect timeout): **2 ثانية**.
   - مهلة قراءة للـ health check: **5 ثوانٍ**.
   - إعادة محاولة واحدة فقط (مرة واحدة) مع تأخير **500ms** — تجنّب حلقات إعادة المحاولة الطويلة على خدمة محلية.
5. **معالجة الأخطاء:**
   - `ECONNREFUSED` / مهلة → اعتبر المزوّد **غير متاح**، وانتقل لمسار التدهور الآمن (القسم 10).
   - `401` مع `signin_url` → يظهر فقط عند `UseAuth()` أو الاتصال بـ `ollama.com` (انظر `api/client.go` → `auth.Sign`). محليًا افتراضيًا لا مصادقة — أي `401` محلي **غير متوقع** ويُعامل كخطأ إعداد.
   - لا تُحاول تشغيل `ollama serve` تلقائيًا من التطبيق؛ الاكتشاف **قراءة فقط**.

**تسلسل مقترح (توضيح سلوكي، ليس كودًا تنفيذيًا):**

> حاول `GET {OLLAMA_HOST}/api/version` بمهلة 5 ثوانٍ. إن نجح، اعتبر المزوّد متاحًا وانتقل إلى `GET /api/tags` لجلب النماذج المثبتة. إن فشل بالاتصال أو المهلة، اعتبر المزوّد غير متاح وشغّل التطبيق بدون ذكاء اصطناعي مع رسالة للمستخدم تشرح كيفية تشغيل Ollama.

## 4. نقاط API الفعلية المستخدمة (مُتحقق من `docs/api.md` و`docs/openapi.yaml` و`api/types.go` و`api/client.go`)

**الخادم:** `http://127.0.0.1:11434` (أو قيمة `OLLAMA_HOST`) — جميع المسارات تحت `/api`.

| المسار | الطريقة | الغرض المُتحقق | ملاحظات مُتحقق منها |
| --- | --- | --- | --- |
| `/api/version` | `GET` | إرجاع نسخة Ollama `{"version": "x.y.z"}` | لا يحتاج جسم طلب. مُستخدم للـ health check. |
| `/api/tags` | `GET` | **سرد النماذج المتاحة محليًا** | يُرجع `{"models": [{"name": "llama3.2:latest", "model": "...", "size": 2019393189, "digest": "...", "details": {"family": "llama", "parameter_size": "3.2B", "quantization_level": "Q4_K_M"}, "modified_at": "…"}]}` — مُتحقق من `docs/api.md` و`openapi.yaml`. |
| `/api/ps` | `GET` | **سرد النماذج المحمّلة حاليًا في الذاكرة** | يُرجع `expires_at` و`size_vram` و`context_length`. |
| `/api/show` | `POST` | تفاصيل نموذج: `modelfile`, `template`, `parameters`, `license`, `details`, `model_info`, `capabilities`, `thinking` | جسمه `{"model": "gemma4", "verbose": false}` — `verbose` اختياري. |
| `/api/generate` | `POST` | توليد إكمال من prompt واحد | جسمه `model` (مطلوب) + `prompt` + `suffix` + `images` (base64) + `system`/`template`/`raw`/`format` (`json` أو JSON schema) + `options` (مثل `temperature`) + `stream` (افتراضي `true`) + `keep_alive` + `think` + `logprobs`. تدفق NDJSON عند `stream: true`، وكائن واحد عند `false`. |
| `/api/chat` | `POST` | توليد دردشة متعددة الأدوار + أدوات (tools) | جسمه `model` + `messages: [{role: system/user/assistant/tool, content, images, tool_calls}]` + `tools: [{type: function, function: {name, description, parameters}}]` + `format` + `options` + `stream` + `keep_alive` + `think`. يدعم الصور لكل رسالة. |
| `/api/embed` | `POST` | **توليد embeddings (الواجهة الحديثة)** | جسمه `model` + `input: string | string[] | object[]` حيث يمكن لكل عنصر حمل `text` و`image` (base64) و`audio` (base64) — `video` غير مدعوم حاليًا (مُتحقق من `docs/api.md: video is not currently accepted`). دعم `truncate` و`dimensions` و`keep_alive`. يُرجع `{"embeddings": [[...]], "total_duration", "load_duration", "prompt_eval_count"}`. |
| `/api/embeddings` | `POST` | توليد embedding واحد (مهجور لصالح `/api/embed`) | جسمه `model` + `prompt` — يُرجع `{"embedding": [...]}`. مذكور في `docs/api.md: superseded by /api/embed`. |
| `/api/pull` | `POST` | **تنزيل نموذج من مكتبة Ollama** | جسمه `model` + `insecure` + `stream`. تدفق حالات: `pulling manifest` → `pulling digestname` مع `total`/`completed` → `verifying sha256 digest` → `writing manifest` → `success`. قابلة للاستئناف عند الإلغاء. **يتطلب تأكيد المستخدم (انظر القسم 7).** |
| `/api/push` | `POST` | رفع نموذج إلى المكتبة (يتطلب تسجيلًا ومفتاحًا) | **غير مطلوب للتطبيق** — يُذكر للاكتمال فقط. |
| `/api/create` | `POST` | إنشاء نموذج جديد من نموذج قائم أو ملفات GGUF/safetensors | جسمه `model` + `from` أو `files: {filename: "sha256:…"}` + `template`/`system`/`parameters`/`messages`/`license`/`quantize`. يتطلب دفع blobs مسبقًا عبر `/api/blobs/:digest`. |
| `/api/blobs/:digest` | `HEAD` / `POST` | فحص وجود blob أو رفعه | `HEAD` يتحقق من وجوده، `POST` يرفع `application/octet-stream` بالـ digest `sha256:…`. |
| `/api/copy` | `POST` | نسخ نموذج باسم جديد | جسمه `{"source": "llama3.2", "destination": "llama3-backup"}` — يُرجع 200 أو 404. |
| `/api/delete` | `DELETE` | حذف نموذج وبياناته | جسمه `{"model": "llama3:13b"}` — يُرجع 200 أو 404. |
| `/v1/systemone` | `POST` | إجابة أسئلة مصنفة/نعم-لا/تقييم بنماذج Decision (مثل `nimble`, `tev`) | **خارج نطاق الاستخدام المقترح حاليًا** — يتطلب `v0.35.0+` ومحدوديات 64 سؤالًا و64KiB نص — يُذكر للعلم فقط. |

**تفاصيل نقلية مُتحققة:**

- **التدفق (streaming):** `generate` و`chat` و`pull` و`create` تدعم `stream: true` افتراضيًا وتُرجع `application/x-ndjson` سطرًا سطرًا مع `done: false` ثم كائن نهائي `done: true` يحمل الإحصاءات (`total_duration` و`load_duration` و`prompt_eval_count` و`eval_count` — جميعها بالنانوثانية). في `api/client.go` حجم المخزن المؤقت مضبوط `maxBufferSize = 8 * format.MegaByte`.
- **التنسيق المنظم:** `format: "json"` أو JSON schema يُجبر النموذج على إخراج JSON صالح — لكن الوثائق تشدد: «من المهم أيضًا توجيه النموذج في `prompt`/`messages` ليُجيب بصيغة JSON».
- **الوسائط:** `images` كـ base64 في `generate` و`chat`، و`input` في `/api/embed` يمكن أن يحمل كائنات `{text, image, audio}` — كل عنصر يملك وسائطه الخاصة.
- **Keep alive:** في كل من `generate` و`chat` و`embed` يمكن ضبط `keep_alive: "5m"` أو `0` لتفريغ النموذج فورًا، أو قيمة سالبة لإبقائه للأبد (انظر `envconfig.KeepAlive`).

> **غير متحقق:** سلوك الخادم عند تجاوز `OLLAMA_MAX_QUEUE` أو عند المنافسة على GPU — الوثائق لا تصف رمز الخطأ بالضبط، لذا يُعامل أي `429`/`503` مستقبليًا كـ `rate_limited` أو `overloaded` ويُطبّق عليه التدهور الآمن.

## 5. إدارة النماذج والتثبيت

### 5.1 التثبيت (مُتحقق من `README.md`)

- **macOS / Linux:** `curl -fsSL https://ollama.com/install.sh | sh` (أو تنزيل `Ollama.dmg`).
- **Windows:** `irm https://ollama.com/install.ps1 | iex` (أو `OllamaSetup.exe`).
- **Docker:** الصورة الرسمية `ollama/ollama` على Docker Hub.
- **بناء من المصدر:** موثق في `docs/development.md` — غير مطلوب للمستخدم النهائي.

### 5.2 مكان التخزين

- المسار الافتراضي `~/.ollama/models` (أو `OLLAMA_MODELS`).
- كل نموذج مكوّن من طبقات blobs تُعرّف بـ `sha256:…` — تُخزّن مرة واحدة وتُشارك بين الأسماء المنسوخة.

### 5.3 دورة حياة النموذج عبر API

| العملية | النقطة | هل تحتاج شبكة؟ | يحتاج تأكيد؟ |
| --- | --- | --- | --- |
| **سرد المثبت** | `GET /api/tags` | لا — قراءة قرص محلي | لا |
| **عرض التفاصيل** | `POST /api/show` | لا | لا |
| **تنزيل جديد** | `POST /api/pull` | **نعم — ينزّل غيغابايت** | **نعم — إلزامي (القسم 7)** |
| **حذف** | `DELETE /api/delete` | لا | نعم — تأكيد حذف صريح |
| **نسخ/إعادة تسمية** | `POST /api/copy` | لا | لا (عملية محلية) |
| **إنشاء من GGUF** | `POST /api/blobs/:digest` + `POST /api/create` | لا إن كانت الملفات محلية | نعم إن كانت كبيرة |
| **معرفة المحمّل** | `GET /api/ps` | لا | لا |

> **سلوك `pull` المُتحقق:** عند الإلغاء يمكن الاستئناف من حيث توقف، والاستدعاءات المتزامنة لنفس النموذج تشترك في نفس التقدّم — لكن التطبيق **لن يستدعي `pull` إطلاقًا دون تأكيد المستخدم**.

## 6. كيف يختار المستخدم نموذجًا مثبتًا

**المبدأ:** المستخدم يختار فقط من قائمة **مثبتة فعلًا** يرجعها `GET /api/tags`. لا تُعرض أسماء من الإنترنت، ولا يُقترح تنزيل تلقائي.

**التدفق المقترح:**

1. عند فتح إعدادات الذكاء الاصطناعي، يستدعي التطبيق `GET /api/tags` (بمهلة 10 ثوانٍ).
2. إن فشل الاتصال → اعرض حالة «المزوّد غير متاح — يعمل التطبيق بدون ذكاء اصطناعي» مع زر «إعادة المحاولة».
3. إن نجح لكن `models: []` → اعرض «لا يوجد نموذج مثبت. نزّل نموذجًا من ollama.com/library يدويًا أو عبر زر التنزيل بموافقتك».
4. إن وُجدت نماذج → اعرض قائمة مرتبة حسب `modified_at` تنازليًا، مع إظهار `name` و`parameter_size` و`quantization_level` و`size` (بايت إلى GB) و`family`.
5. يختار المستخدم نموذجًا واحدًا ويُحفظ الاختيار (مثلاً في إعدادات المشروع). يُرسل هذا الاسم حرفيًا في حقل `model` لكل طلب `generate`/`chat`/`embed`.
6. قبل كل طلب تحقق أن الاسم لا يزال في `/api/tags`؛ إن حُذف → أعد التوجيه للاختيار واعرض `model_not_found`.
7. **لا يوجد «نموذج افتراضي» يُنزّل وحده.** إن لم يختر المستخدم، تبقى ميزات الذكاء الاصطناعي معطّلة بصريًا.

**اعتبارات واجهة المستخدم:**

- لا تعرض زر «تنزيل تلقائي لأفضل نموذج» — أي تنزيل يجب أن يمر عبر حوار تأكيد يذكر الحجم التقريبي (من `size` أو من صفحة المكتبة **غير متحقق** حجمها الدقيق قبل `pull`).
- أظهر تحذيرًا عند اختيار نموذج كبير (`parameter_size` ≥ `13B` أو `size` ≥ `8GB` — عتبات **غير متحقق** دقتها لكل جهاز) بأن الأداء قد يكون بطيئًا على أجهزة بلا GPU.
- أتِح خيار «إلغاء تحميل النموذج» عبر `keep_alive: 0` أو `GET /api/ps` + تفريغ.

## 7. القاعدة الصريحة: لا تنزيل لأي نموذج كبير دون تأكيد صريح من المستخدم

> **قاعدة ملزمة — تُعرض في الواجهة وتُطبّق في الكود المستقبلي (غير منفّذ في هذه المرحلة التوثيقية):**
>
> **«التطبيق لا ينزّل — ولا يبدأ حتى — تنزيل أي نموذج أو طبقة كبيرة عبر `POST /api/pull` أو `POST /api/blobs` أو `POST /api/create` إلا بعد حصوله على تأكيد صريح ومستنير من المستخدم في نفس الجلسة. التنزيل التلقائي أو الضمني في الخلفية محظور تمامًا.»**

**ما يعنيه ذلك عمليًا:**

- لا استدعاء لـ `/api/pull` عند أول تشغيل، ولا عند فشل `model_not_found`، ولا كـ fallback.
- زر «تنزيل» منفصل يفتح حوارًا يوضح: اسم النموذج، المصدر (`ollama.com/library/<name>`), الحجم التقريبي (إن عُرف من `pull` الأولي `total` — **غير متحقق** مسبقًا بدقة)، ومتطلبات القرص، وأن العملية قد تستغرق دقائق/ساعات حسب الشبكة.
- يتطلب الحوار **نقرًا صريحًا** على «تأكيد التنزيل» — لا يكفي تفعيل مفتاح `enableAI`.
- يمكن إلغاء التنزيل في أي لحظة؛ الإلغاء يُوقف `pull` ويترك الأجزاء للاستئناف لاحقًا (سلوك Ollama المُتحقق)، لكن التطبيق لا يستأنف تلقائيًا دون تأكيد جديد.
- أي محاولة برمجية لتجاوز هذه القاعدة تُعد خرقًا للمواصفة ويجب أن تفشل في المراجعة.

## 8. نطاقات Embeddings

- **الواجهة الحديثة:** `POST /api/embed` — مُوصى بها. تدعم نصًا واحدًا أو قائمة نصوص أو كائنات متعددة الوسائط `{text, image, audio}`، مع `truncate` و`dimensions`.
- **الواجهة المهجورة:** `POST /api/embeddings` — تبقى للتوافق، لكن `docs/api.md` يصرّح `superseded by /api/embed`. التطبيق المستقبلي يستخدم `/api/embed` فقط.
- **الاستخدامات المقترحة:** البحث الدلالي داخل نتائج التحقيق، كشف التكرار الدلالي (قسم 9.3)، وترتيب النتائج حسب التشابه — لكن كل ذلك **اختياري** ويعمل فقط إن كان نموذج embeddings مثبتًا (مثل `all-minilm` أو `embeddinggemma` — أسماء **غير متحقق** توفرها محليًا قبل `GET /api/tags`).
- **التحقق:** لا تفترض وجود نموذج embeddings؛ تحقق عبر `/api/tags` أن الاسم المطلوب موجود قبل الاستدعاء، وإلا اعتبر الميزة غير متاحة.

## 9. أنماط الاستخدام المقترحة (6 أنماط)

> جميع الأنماط **اختيارية**، تعمل فقط عند توفر مزوّد ونموذج مختار، وتُغلّف بنفس الواجهة المجرّدة (القسم 11). المخرجات دائمًا موسومة `ai_generated` ومفصولة عن الحقائق المتحققة.

### 9.1 تلخيص نتائج البحث (Summarize Search Results)

- **الهدف:** تحويل قائمة نتائج OSINT/بحث إلى فقرة موجزة بالعربية مع الحفاظ على المصادر.
- **المدخل:** قائمة نتائج موحّدة (كل نتيجة تحمل `source.name` و`source.url` و`evidence` الخام).
- **المخرج:** ملخص فقري + قائمة نقاط + استشهادات مرقمة — كل جملة مولدة موسومة `ai_generated`، والروابط الأصلية موسومة `source_verified`.
- **الضوابط:** حد أقصى للإدخال (مثلاً 8K حرف) مع اقتطاع ذكي، ودرجة حرارة منخفضة (`temperature: 0.2` **غير متحقق** أثرها الدقيق لكل نموذج).

### 9.2 تصنيف النتائج (Classify Results)

- **الهدف:** وسم كل نتيجة بفئة (`found`/`not_found`/`uncertain`/`needs_review`) ومستوى ثقة.
- **المدخل:** نتيجة واحدة أو دفعة صغيرة (≤10).
- **المخرج:** `{"label": "…", "confidence": "high|medium|low", "reason": "…"} ` مع `provenance: ai_generated`.
- **الضوابط:** استخدم `format: json` مع JSON schema لضمان مخرجات قابلة للتحليل؛ ارفض أي مخرج لا يطابق المخطط واعتبره `error`.

### 9.3 كشف النتائج المكررة (Duplicate Detection)

- **الهدف:** تحديد نتائج تشير لنفس الكيان عبر مصادر مختلفة.
- **الخيار A (دلالي):** عبر `/api/embed` — احسب تشابه جيب التمام بين المتجهات؛ عتبة مثل `0.92` **غير متحقق** عمومًا وتحتاج معايرة.
- **الخيار B (لغوي):** عبر `chat` — اطلب من النموذج مقارنة زوج نتائج وإخراج `{"duplicate": true|false, "reason": "…"}`.
- **المخرج:** مجموعات تكرار مع `evidence` من المصادر الأصلية (`source_verified`) وتفسير التجميع (`ai_generated`).

### 9.4 شرح علاقات المصادر (Explain Source Relations)

- **الهدف:** رسم علاقات بين المصادر (مثلاً: نفس اسم المستخدم على شبكتين يعود لنفس الشخص **احتمالًا**).
- **المخرج:** وصف علاقة مع `confidence` و`explanation` موسومين `ai_generated`، مع إبقاء الروابط الأصلية `source_verified`.
- **تحذير:** لا يُستخدم لإثبات هوية — يُعرض كـ «اقتراح يحتاج تحققًا بشريًا».

### 9.5 توليد التقارير (Generate Reports)

- **الهدف:** تجميع ملخص تنفيذي + تفاصيل لكل أداة + جدول زمني.
- **المدخل:** نتائج موحّدة + ملاحظات المحقق.
- **المخرج:** تقرير منظم بعناوين، مع قسم «حقائق متحققة من المصدر» (منسوخ حرفيًا من `evidence`) وقسم «تحليل مولّد بالذكاء الاصطناعي» مفصول بوضوح.
- **الضوابط:** استخدم `format: json` أو قالبًا يفرض أقسامًا ثابتة؛ امنع هلوسة روابط — أي رابط في التقرير يجب أن يكون موجودًا أصلًا في المدخلات وإلا يُحذف.

### 9.6 تلخيص التحقيق (Summarize Investigation)

- **الهدف:** تلخيص تحقيق كامل (متعدد الخطوات) في فقرة قابلة للمشاركة.
- **الفرق عن 9.1:** يغطي كامل التحقيق لا بحثًا واحدًا، ويشمل توصيات «خطوات تالية».
- **المخرج:** ملخص + نقاط رئيسية + «ما لم يُتحقق» — كل توصية موسومة `ai_generated` وتحتاج موافقة بشرية قبل التنفيذ.

## 10. استراتيجيات المهلات وحدود المعدل

### 10.1 المهلات (Timeouts)

| العملية | مهلة مقترحة | السبب |
| --- | --- | --- |
| `GET /api/version` (اكتشاف) | **5 ثوانٍ** إجمالية (اتصال 2 ثانية) | فحص خفيف |
| `GET /api/tags` / `GET /api/ps` / `POST /api/show` | **10 ثوانٍ** | قراءة قرص + JSON |
| `POST /api/generate` / `POST /api/chat` (غير متدفق) | **60 ثانية** افتراضية، قابلة للزيادة إلى **120 ثانية** للتقارير الطويلة | توليد قد يطول؛ يعتمد على `num_predict` وطول السياق |
| `POST /api/embed` | **30 ثانية** | أسرع من التوليد |
| `POST /api/pull` (تنزيل) | **بلا مهلة ثابتة** — اعتمد تقدم `total`/`completed` مع مهلة خمول **60 ثانية** بلا تقدم | قد يستغرق ساعات |
| تحميل النموذج (load) | احترم `OLLAMA_LOAD_TIMEOUT` (افتراضي `5m`) على الخادم؛ على العميل اعتبر `5 دقائق` كحد أعلى للانتظار قبل إلغاء الطلب | مُتحقق من `envconfig.LoadTimeout()` |

**آليات الإلغاء:**

- استخدم `AbortController`/`AbortSignal` على مستوى الطلب — عند انتهاء المهلة ألغِ الطلب واعرض `timeout`.
- لا تُعيد المحاولة تلقائيًا لطلبات `generate`/`chat` — فشل واحد يُعالج بالتدهور الآمن.
- للتدفق (`stream: true`) اعتبر أي صمت > **15 ثانية** بلا chunk كمهلة تدفق.

### 10.2 حدود المعدل (Rate Limits)

- **Ollama المحلي لا يفرض حد معدل شبكي مُوثق** — الحدود الحقيقية هي `OLLAMA_NUM_PARALLEL` و`OLLAMA_MAX_QUEUE=512` و`OLLAMA_MAX_LOADED_MODELS` على الخادم. قيمها الافتراضية `0` تعني «يختار الخلفية» — السلوك الدقيق **غير متحقق** بدون تشغيل فعلي.
- **حدود مقترحة على مستوى التطبيق (لحماية الجهاز):**

| النطاق | الحد المقترح |
| --- | --- |
| طلبات `generate`/`chat` لكل مستخدم | **1 طلب متزامن** + طابور **2** كحد أقصى؛ أي طلب ثالث يُرفض فورًا `rate_limited` |
| طلبات `embed` | **5 طلبات/ثانية** لكل مستخدم (دُفعات صغيرة) |
| استدعاءات `pull` | **عملية واحدة متزامنة** على مستوى التطبيق كاملًا |
| إجمالي يومي للذكاء الاصطناعي | **غير متحقق** — يُترك لإعداد المشرف، افتراضي بلا حد لكن مع مراقبة |

### 10.3 إعادة المحاولة (Retries)

- **لا تُعد المحاولة** لطلبات `generate`/`chat`/`embed` الفاشلة بسبب مهلة أو خطأ نموذج — انتقل للتدهور الآمن فورًا.
- **استثناء وحيد:** فشل `GET /api/tags` العابر (مرة واحدة) يمكن إعادة محاولته مرة واحدة بعد 500ms.
- سجّل كل فشل مع `provider`, `model`, `task`, `duration_ms`, `error` لكن **لا تسجل محتوى موجّه** دون موافقة.

## 11. واجهة مجرّدة مقترحة لمزوّد الذكاء الاصطناعي

> **تحذير:** هذا القسم **اقتراح توثيقي فقط** — لا يوجد كود تنفيذ في هذا المستودع، ولا يُبنى عليه قبل اعتماده. الهدف توحيد استدعاء Ollama وأي مزوّد ثانٍ (مثل مزوّد OpenAI-compatible) خلف عقد واحد.

### 11.1 المبادئ

1. **حياد المزوّد:** التطبيق لا يعرف إن كان المزوّد Ollama محليًا أم مزوّدًا ثانٍ سحابيًا — يرى واجهة واحدة.
2. **فصل المصدر:** كل حقل في المخرجات موسوم `provenance: "ai_generated" | "source_verified"` — لا يُخلط المولّد بالمتحقق.
3. **تدهور آمن:** أي فشل في المزوّد يُرجع `status: provider_unavailable` ويعمل التطبيق كاملاً بدون ذكاء اصطناعي.
4. **لا تنزيل ضمني:** الواجهة لا تستدعي `pull`/`create`/`push` إطلاقًا إلا عبر مسار تأكيد منفصل (القسم 7).
5. **JSON أولًا:** جميع العقود JSON مع `format: json` أو JSON schema حيث أمكن.

### 11.2 عقد الإدخال المقترح (JSON)

```json
{

  "model": "string — اسم من GET /api/tags عند provider=ollama",

  "locale": "ar",
  "input": {
    "query": { "type": "username|email|phone|mixed", "value": "string" },
    "results": [
      {
        "tool": "sherlock|maigret|…",
        "source": { "name": "string", "url": "string|null" },
        "status": "found|not_found|error|skipped",
        "evidence": "string — النص الخام من المصدر",
        "started_at": "ISO-8601 UTC",
        "duration_ms": 0
      }
    ],
    "options": {
      "max_chars": 8000,
      "temperature": 0.2,
      "format": "json",
      "keep_alive": "5m"
    }
  },
  "context": {
    "investigation_id": "uuid",
    "user_id": "string",
```

### 11.4 وسم المولّد مقابل المتحقق

| الحقل | الوسم | المعنى |
| --- | --- | --- |
| `result.summary` / `result.points` / `result.relations[*].explanation` | `provenance: ai_generated` | نص أنشأه النموذج — يحتاج تحققًا بشريًا |
| `input.results[*].evidence` / `citations[*]` | `provenance: source_verified` | نص/رابط أعيد حرفيًا من المصدر أو من استدعاء أداة OSINT |
| `result.report.sections` | كل قسم يحمل `provenance` خاصًا به | لا يُخلط قسما «حقائق» و«تحليل» |
| رسائل الواجهة | شارة مرئية «مولّد بالذكاء الاصطناعي» مقابل «متحقق من المصدر» | مع تلميح يوضح أن الأول قد يحوي هلوسة |

**قاعدة عرض:**

- أي نص `ai_generated` يُعرض مع شارة صفراء/زرقاء «ذكاء اصطناعي — غير متحقق» ورابط «عرض المصادر».
- أي نص `source_verified` يُعرض مع شارة خضراء «متحقق من المصدر» ورابط المصدر الأصلي.
- لا يُنسخ نص `ai_generated` إلى حقول `evidence` أو `source.url` — الفصل ثنائي الاتجاه.

### 11.5 الواجهة المجرّدة (توصيف سلوكي، ليس كودًا)

- **عملية واحدة موحّدة:** `invoke(task, input) -> output` حيث `task` أحد الأنماط الستة.
- **الاختيار:** المصنع يختار `OllamaProvider` إن كان `OLLAMA_HOST` متاحًا و`GET /api/version` ناجحًا، وإلا `SecondProvider` إن كان مهيأً، وإلا `NoopProvider` (تدهور آمن).
- **التوقيع الموحّد:** جميع المزوّدين يطبّقون نفس عقدي JSON أعلاه — Ollama يترجمها إلى `POST /api/generate` أو `POST /api/chat` أو `POST /api/embed` حسب `task`، والمزوّد الثاني يترجمها إلى واجهته الخاصة.
- **الأخطاء الموحّدة:** أي مزوّد يُرجع نفس قيم `status` — التطبيق يعالجها بنفس مسار التدهور.

## 12. مسار التدهور الآمن — العمل كاملاً بدون ذكاء اصطناعي

> **قاعدة ملزمة:** عند تعذر المزوّد (خادم غير مكتشف، نموذج غير مثبت، مهلة، خطأ، حد معدل، أو رفض المستخدم للتنزيل) **يعمل التطبيق كاملاً بدون ذكاء اصطناعي** — لا تتوقف أي ميزة أساسية.

**السلوك المحدد:**

| حالة الفشل | `status` المُرجع | سلوك التطبيق |
| --- | --- | --- |
| `GET /api/version` فشل (اتصال/مهلة) | `provider_unavailable` | إخفاء أقسام الذكاء الاصطناعي، عرض تنبيه «الميزات الذكية غير متاحة — التطبيق يعمل بدونها»، السماح بإعادة المحاولة |
| `GET /api/tags` فارغ | `model_not_found` + `meta.fallback=true` | عرض «لا نموذج مثبت» مع رابط لتوثيق التثبيت، لا محاولة تنزيل |
| `POST /api/generate` مهلة/خطأ | `timeout` / `error` | عرض «تعذر التوليد — حاول لاحقًا» مع إبقاء النتائج المتحققة ظاهرة |
| حد المعدل/الطابور ممتلئ | `rate_limited` | رسالة «الطلبات كثيرة — انتظر ثوانٍ» |
| المستخدم رفض التنزيل | `skipped` | لا إعادة طلب تلقائية |

**ضمانات:**

- لا يُحجب أي مسار OSINT (Sherlock/Maigret/…) بسبب فشل الذكاء الاصطناعي.
- لا يُطلب من المستخدم إدخال مفتاح أو تنزيل للمتابعة — التطبيق مكتمل بدونه.
- جميع الميزات الذكية **opt-in** بصريًا: أزرارها معطّلة مع تلميح يشرح السبب عند عدم التوفر.

## 13. متطلبات التشغيل المحلي بلا اتصال

**الهدف:** بعد الإعداد الأولي، يعمل كل شيء بلا إنترنت.

| المتطلب | التفاصيل المُتحققة | ملاحظات |
| --- | --- | --- |
| **تثبيت Ollama** | ثنائي Ollama (عبر `install.sh` أو `OllamaSetup.exe` أو صورة `ollama/ollama`) | يحتاج اتصالًا مرة واحدة للتنزيل — بعدها بلا شبكة |
| **نموذج واحد على الأقل** | أي نموذج من `ollama.com/library` يُنزّل عبر `ollama pull <name>` أو `POST /api/pull` **بتأكيد المستخدم** | الحجم **غامت GB** (مثلاً `llama3.2: 2GB`, `deepseek-r1: 4.6GB` كأمثلة من `docs/api.md` — أحجام **غير متحقق** ثباتها) — يحتاج قرصًا كافيًا |
| **مسار التخزين** | `~/.ollama/models` أو `OLLAMA_MODELS` | تأكد من مساحة حرة ≥ حجم النموذج + 10% هامش |
| **الذاكرة** | `OLLAMA_KEEP_ALIVE=5m` افتراضيًا — النموذج يُحمّل في RAM/VRAM عند أول طلب | `GET /api/ps` يظهر `size_vram` — القيم **غير متحقق** بدون تشغيل فعلي |
| **الشبكة بعد الإعداد** | **صفر طلب خارجي** — كل من `generate` و`chat` و`embed` و`tags` و`show` محلية تمامًا | تحقق بعدم وجود `OLLAMA_REMOTES` مخصص أو `ollama.com` كـ `OLLAMA_HOST` |
| **التحديثات** | لا تحديث تلقائي للنماذج — `pull` جديدة فقط بتأكيد المستخدم |  |
| **النسخ الاحتياطي** | نسخ مجلد `OLLAMA_MODELS` يكفي لنقل النماذج لجهاز آخر |  |

**قائمة تحقق قبل وضع «بلا اتصال»:**

1. `GET /api/version` ينجح بلا إنترنت.
2. `GET /api/tags` يُرجع النموذج المطلوب.
3. `POST /api/generate` مع `{"model": "<المختار>", "prompt": "ping", "stream": false}` ينجح بمهلة 30 ثانية.
4. فصل الشبكة وإعادة نفس الاختبارات — يجب أن تنجح جميعها.

## 14. قيود معروفة

1. **عدم التشغيل الفعلي:** لم يُشغّل خادم Ollama فعليًا في هذا البحث — كل السلوكيات الزمنية والاستهلاكية **غير متحقق** ميدانيًا.
2. **أحجام النماذج:** أحجام `size` في أمثلة `docs/api.md` لحظية وقد تختلف بين الإصدارات والكميات (`Q4_K_M` مقابل `Q4_0`).
3. **حدود السياق:** `num_ctx` و`context_length` تختلف per نموذج — القيم في `ShowResponse.model_info` **غير متحقق** دون استدعاء `POST /api/show` لنموذج بعينه.
4. **المزوّد الثاني:** لم يُسمّ مزوّد ثانٍ محدد في نص المهمة — الواجهة المجرّدة هنا محايدة وتدعم أي مزوّد OpenAI-compatible مستقبلًا، لكن تفاصيله **غير متحقق**.
5. **النجوم والإصدارات:** أرقام `stargazers` و`pushed_at` لحظية في 2026-11-26 وتتغير.
6. **السلوك عند امتلاء الطابور:** رمز الخطأ عند تجاوز `OLLAMA_MAX_QUEUE` **غير متحقق** من الوثائق — يُعامل كـ `rate_limited`/`overloaded` مع تدهور آمن.

## 15. العمل المتبقي (لا كود في هذه المرحلة)

1. **اعتماد عقد JSON** في القسم 11 مع الفريق — مطابقة الحقول مع مخطط النتيجة الموحّد للأدوات (البند 7 في `INTEGRATIONS_EVALUATION.md`).
2. **مراجعة قانونية** لترخيص MIT وتأكيد عدم وجود التزامات إضافية عند توزيع صورة تحوي Ollama.
3. **قياس ميداني** لمهلات `generate`/`chat` على نموذجين صغيرين (مثل `llama3.2:3b` و`all-minilm` لل embeddings) على جهاز مرجعي بلا GPU — تحويل «غير متحقق» إلى أرقام مقيسة.
4. **اختبار اكتشاف** `GET /api/version` مع `OLLAMA_HOST` مخصص ومنفذ مختلف و`0.0.0.0`.
5. **تصميم حوار تأكيد التنزيل** (UI) مع عرض الحجم والتقدير الزمني — لا يُنفّذ `pull` قبل اعتماده.
6. **لا يُضاف أي Adapter/Provider تنفيذي** حتى استكمال 1–4 واعتماد هذه الوثيقة.
