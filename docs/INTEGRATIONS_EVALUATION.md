# تقييم أدوات OSINT — Integrations Evaluation

**المهمة:** بحث وتوثيق لتقييم أدوات OSINT التالية قبل أي دمج فعلي:
`Sherlock` · `Maigret` · `PhoneInfoga` · `OpenOSINT` · `Holehe`

**النطاق:** توثيق فقط. لا يوجد — ولا يُضاف — أي كود تكامل (adapters) في هذا المستودع.

**تاريخ البحث:** 2026-11-26 (UTC). جميع الأرقام مأخوذة من واجهات GitHub API و PyPI API
ومن قراءة الشيفرة المصدرية للوسوم/الفروع الافتراضية في هذا التاريخ.

> ### منهجية التحقق
> استُخدم لتثبيت الحقائق: `api.github.com` (بيانات المستودع، وسم آخر إصدار، تاريخ آخر إصدار،
> تاريخ آخر commit)، `pypi.org/pypi/<pkg>/json` (الإصدار، `requires_python`، الاعتماديات،
> تاريخ الرفع)، وتنزيل أرشيفات `codeload.github.com` لقراءة `pyproject.toml` / `setup.py` /
> `go.mod` / `settings.json` / شيفرة المحلّلات.
>
> كل ما لم يُتحقّق منه بهذه الطريقة — خصوصاً **أعداد الطلبات الشبكية الفعلية**، و**إصدارات
> الدعم على مستوى كل منصّة**، و**عدد النجوم** حيث لم يُقرأ من الـ API — موسوم صراحةً بعبارة
> **«غير متحقق»**. لا تُفهم أي خلية في هذا الملف على أنها استنتاج من الشعارات أو القراءة العامّة
> للمشاريع.

## البند 7 المرجعي — مخطط النتيجة الموحّد

يشير تقييم المهمة إلى «مخطط النتيجة الموحّد في البند 7». لم يتضمّن نصّ المهمة المتاح تعريفاً
صريحاً للمخطط، لذلك اعتُمد هنا مخطط وسيط محافظ يُستخدم في عمود **تصميم المحوّل** أدناه.
**هذا المخطط هو اقتراح توثيقي، ويجب مطابقته مع تعريف البند 7 الرسمي قبل أي تنفيذ.**

```json
{
  "tool": "string",
  "query": { "type": "username|email|phone|mixed", "value": "string" },
  "status": "found|not_found|rate_limited|error|skipped",
  "confidence": "high|medium|low",
  "source": { "name": "site or provider", "url": "string|null" },
  "evidence": "string (raw snippet / reason, optional)",
  "started_at": "ISO-8601 UTC",
  "duration_ms": 0,
  "error": "string|null",
  "meta": { "attribution": "tool + version", "partial": false }
}
```

المبادئ الملزمة للمحوّل: نتيجة واحدة لكل (أداة، مصدر)، لا استنتاج `not_found` عند حجب أو
مهلة (يُسجّل `error`/`skipped`)، ونقل النص الخام في `evidence` دون إعادة تفسيره.

## 2. بطاقات الأدوات

### 2.1 Sherlock — بحث أسماء المستخدمين

- **الوظيفة:** التحقق من وجود اسم مستخدم على شبكات اجتماعية عبر طلب صفحة الملف المتوقّعة.
- **الاعتماديات (من `pyproject.toml`):** `certifi`, `colorama`, `PySocks`, `requests`,
  `requests-futures`, `stem`, `pandas`, `openpyxl`, `tomli`.
- **السلوك الشبكي:**
  - يستخدم `FuturesSession` بحد أقصى **20 عاملًا متزامناً** (مقروء من `sherlock.py`).
  - يحمّل قاعدة المواقع من `https://data.sherlockproject.xyz` على الشبكة (مهلة 30 ثانية)
    بدلاً من الملف المرفق، ما لم يُمرَّر `--local`.
  - يجلب أيضاً `false_positive_exclusions.txt` من GitHub (مهلة 10 ثوانٍ)، ويستعلم
    `api.github.com/.../releases/latest` لفحص التحديث (مهلة 10 ثوانٍ) عند كل تشغيل.
  - المهلة الافتراضية لكل موقع: **60 ثانية** (`--timeout`)، أي أن الأسوأ قد يبلغ دقائق.
  - يدعم `--proxy` فقط؛ **خيار `--tor` لم يعد موجوداً في CLI الحالي** (تحقّق بالبحث في
    `sherlock.py`: لا وجود له)، لذا استخدام Tor يحتاج `--proxy socks5://…` يدوياً.
  - عدد الطلبات الفعلي لكل موقع (1 أم أكثر) يختلف حسب الموقع؛ **غير متحقق** عملياً.
- **المخرجات:** نص/CSV/XLSX/JSON؛ الحالات `Claimed / Available / Unknown / Illegal / WAF`.
- **التوصية: ✅ مفعّلة في مرحلة لاحقة.** MIT، صيانة نشطة، واجهة CLI مستقرّة، ولا مفاتيح.
  تُشغَّل بميزانية طلبات محدودة وموقع محدود (tag/allow-list) بدل القاعدة الكاملة.

**تصميم المحوّل المقترح (Sherlock)**

| البند | التصميم |
| --- | --- |
| نقطة الدخول | `sherlock <username> --json <file> --print-found --timeout 10 [--site …]`؛ استدعاء subprocess، وتفريغ JSON إلى مخطط البند 7 |
| المهلات | مهلة لكل موقع 5–10 ثوانٍ، ومهلة إجمالية صارمة 90 ثانية للعملية كاملة |
| حدود المعدل | ≤ 10 عمال (`--max-connections` لا يوجد؛ الحد من داخل الأداة = 20)، وعلى مستوى المنصة: طلب واحد لكل مستخدم في الدقيقة، وسقف يومي |
| آلية الإلغاء | `Popen` في مجموعة عمليات + `SIGTERM` ثم `SIGKILL` بعد 5 ثوانٍ؛ عند مهلة إجمالية يُعاد ما تمّ تجميعه مع `meta.partial=true` |
| تطبيع المخرجات | لكل موقع بسطر: `tool=sherlock`, `query.type=username`, `source.name=<site>`, `source.url=<url_user>`, `status=found` إذا `Claimed` و`not_found` إذا `Available`، و`error` لكل من `Unknown`/`WAF`/`Illegal` مع `evidence=context` |

### 2.2 Maigret — بحث أسماء المستخدمات الموسّع

- **الوظيفة:** امتداد لفكرة Sherlock بـ **11,640 موقعاً** في `resources/data.json` المرفق
  (تحقّق عدّ آلي)، مع بحث متكرّر عن معرّفات إضافية مستخرجة من الصفحات (`--no-recursion` لإيقافه).
- **الاعتماديات:** 28 حزمة (الأثقل: `lxml`, `curl-cffi`, `aiohttp`, `flask`, `reportlab`,
  `networkx`, `pyvis`, `XMind`, `Jinja2`). PDF اختياري (`maigret[pdf]`).
- **السلوك الشبكي (من `resources/settings.json`):**
  - `max_connections: 100` (حتى 100 اتصال متزامن).
  - `timeout: 30` ثانية لكل طلب، `retries_count: 0`.
  - `top_sites_count: 500` افتراضياً (أي ~500 موقع في التشغيل الافتراضي، لا 11,640)،
    و`--all-sites` لفتح المجموع الكامل.
  - تحديث تلقائي لقاعدة المواقع من GitHub كل 24 ساعة (`db_update_meta_url`)؛ يمكن تعطيله.
  - يدعم `--proxy`, `--tor-proxy` (`socks5://127.0.0.1:9050`), `--i2p-proxy`.
  - تكامل `FlareSolverr` اختياري لمحاولة تجاوز Cloudflare.
  - استخراج معلومات إضافية (`info_extracting: true`) يزيد الطلبات؛ العدد الفعلي **غير متحقق**.
- **المخرجات:** نص/CSV/JSON/HTML/MD/PDF/XMind/رسوم بيانية.
- **التوصية: ✅ مفعّلة في مرحلة لاحقة، بحدود أضيق من Sherlock.** MIT وصيانة يومية، لكن
  100 اتصال + 500 موقع + بحث متكرّر = بصمة شبكية كبيرة ومعدّل فشل/حجب أعلى. تُشغَّل بقائمة
  مواقع صغيرة (`--top-sites 50` أو `--site`)، وبلا تكامل FlareSolverr.

**تصميم المحوّل المقترح (Maigret)**

| البند | التصميم |
| --- | --- |
| نقطة الدخول | `maigret <username> --json ndjson --top-sites 50 --no-recursion --timeout 15 -n 20` (قاعدة المواقع مستخدمة محلياً مع `--no-autoupdate` لتفادي طلبات GitHub) |
| المهلات | 15 ثانية/طلب، 120 ثانية إجمالية؛ عند انتهائها تسليم جزئي |
| حدود المعدل | `-n 20` كحد أقصى للاتصالات داخل الأداة؛ خارجياً: مستخدم واحد/دقيقة وسقف يومي كـ Sherlock |
| آلية الإلغاء | مجموعة عمليات + `SIGTERM` → `SIGKILL`؛ إلغاء عبر `AbortSignal` في الـ API المستقبلي |
| تطبيع المخرجات | نتيجة لكل موقع: `status` من نتيجة التحقق (`found`/`not_found`)، مع `error` عند الفشل، `meta.partial` عند الإلغاء؛ تُسجَّل المعرّفات الإضافية في `evidence` لا كسجلات مستقلة |

### 2.3 PhoneInfoga — المعلومات من أرقام الهواتف

- **اللغة:** Go (ليست أداة Python) — وهذا يغيّر طريقة التثبيت والاعتماديات كلياً.
- **الصيانة:** **متوقف رسمياً.** الـ README يصرّح: *"This project is stable but unmaintained.
  Upcoming bugs won't be fixed and repository could be archived at any time."*
  آخر Release `v2.11.0` بتاريخ 2024-02-21، وآخر commit 2026-08-25 (تحديثات اختبارات فقط).
- **المحلّلات:**
  - `local`: **بلا أي طلب شبكي** — يستخرج الدولة/الحامل/الصيغ عبر `nyaruka/phonenumbers`.
  - `numverify`: يحتاج `NUMVERIFY_API_KEY` (من apilayer)، ويتحقّق من وجود المفتاح قبل الطلب.
  - `googlecse`: يحتاج `GOOGLE_API_KEY` و`GOOGLECSE_CX`؛ النتائج بحد أقصى 10 لكل صفحة
    (ويمكن رفعها حتى 100 عبر `GOOGLECSE_MAX_RESULTS`).
  - `googlesearch`: **لا ينفّذ طلبات** — يولّد روابط بحث (dorks) فقط.
  - `ovh`: REST API عمومي، مدعوم فقط لرموز الدول 33/32/44/34/41 (فرنسا/بلجيكا/UK/إسبانيا/سويسرا).
  - المحلّلات غير المهيّأة تُتخطّى تلقائياً.
- **الشبكة:** المحلّل المحلي صفر طلب؛ `numverify` طلب واحد لكل رقم؛ `googlecse` حتى 10 نتائج/طلب.
  عدد طلبات `googlecse` الفعلي حسب عدد الصفحات المطلوبة — **غير متحقق** عملياً.
- **التوصية: ⏸️ مؤجّلة.** سببان: (1) الترخيص GPL-3.0 يحتاج مراجعة قانونية، (2) المشروع معلن
  كمتوقف ومرشّح للأرشفة — أي اعتماد عليه يورث ديناً تقنياً. لا يُستبدل به المحلّل المحلي
  القابل للتطبيق داخل مشروعنا مباشرةً إن احتجنا استخراج الدولة/الحامل لاحقاً.

**تصميم المحوّل المقترح (PhoneInfoga) — إن أُقرّ لاحقاً**

| البند | التصميم |
| --- | --- |
| نقطة الدخول | `phoneinfoga scan -n <E.164> --env-file <none>` مع تفعيل المحلّل `local` فقط افتراضياً؛ المحلّلات السحابية بقرار صريح لكل طلب |
| المهلات | 10 ثوانٍ للمحلّل المحلي (لا شبكة)، 30 ثانية لأي محلّل سحابي |
| حدود المعدل | المحلي بلا حدّ شبكي؛ السحابي: طلب واحد/رقم/دقيقة حداً أعلى |
| آلية الإلغاء | subprocess + `SIGTERM`؛ المحلي ينهي فوراً |
| تطبيع المخرجات | سجل واحد لكل محلّل: `source.name=phoneinfoga:<scanner>`، `evidence` = JSON الخام (`e164`, `country`, `carrier`, `line_type`)؛ `status=found` عند وجود بيانات، `skipped` عند غياب مفتاح |

### 2.4 OpenOSINT — مُنسّق (orchestrator) لا أداة بحث بحد ذاتها

- **الوظيفة (من الـ README و`pyproject.toml`):** وكيل OSINT بواجهة لغوية طبيعية + خادم MCP،
  يلفّ **21 أداة** ويستدعي بعض الثنائيات المحلية (`sherlock`, `holehe`, `sublist3r`,
  `phoneinfoga`) التي **يجب تثبيتها منفصلاً**.
- **ملاحظة جوهرية:** OpenOSINT ليس بديلاً عن الأدوات الأربع الأخرى، بل **طبقة تجميع** فوقها.
  اعتماده يعني ضمناً اعتماد Sherlock وHolehe وPhoneInfoga.
- **الاعتماديات:** ~52 اعتمادية، أبرزها `anthropic`, `mcp`, `fastapi`, `uvicorn`, `asyncpg`,
  `cryptography`, `authlib`, `reportlab`, `aiohttp`.
- **مفتاح مدفوع؟** التشغيل الأساسي (`uvx openosint web`, `openosint exposure`) بلا مفاتيح.
  الميزات المعتمدة على مزوّد LLM (`anthropic` افتراضياً، أو `ollama` محلياً) تحتاج مفتاحاً
  أو نموذجاً محلياً. بعض الأدوات الموسومة «Key needed: Yes» تحتاج مفاتيح (Bright Data,
  HIBP, Shodan, Censys, VirusTotal, AbuseIPDB, IP2Location).
- **السلوك الشبكي:**
  - «Passive by default»: الأدوات التي تلمس الهدف أو ترسل طلبات كثيرة **معطّلة** حتى
    `--allow-active`.
  - `tool_policy.py` يصنّف `search_username` و`search_email` و`search_domain` كـ **NOISY**،
    و`search_phone` كـ **UNVERIFIED**، أي أنها تتطلّب وضعاً نشطاً صريحاً.
  - أزمنة المهلة الموثّقة داخلياً: `search_username` → 180 ثانية إجمالية (Sherlock `--timeout`
    داخلي)، `search_email` → 120 ثانية، `search_phone` → 60 ثانية.
  - عدد طلبات كل أداة خارجية لا يزال **غير متحقق** عبر التقاط حركة فعلي (المشروع نفسه يوسمه
    `unverified`).
- **التوصية: ⏸️ مؤجّلة.** MIT ومشروع نشِط، لكنه يضيف طبقة LLM واعتماداً على 4 ثنائيات
  خارجية، ويضاعف سطح الهجوم والاعتماديات. الأنسب لاحقاً: إعادة تقييمه **بعد** تقرير الأدوات
  الأساسية، وربما استخدام `run_username_osint_structured` / كود OpenOSINT كمصدر أفكار
  للتطبيع فقط لا كاعتماد.

**تصميم المحوّل المقترح (OpenOSINT) — إن أُقرّ لاحقاً**

| البند | التصميم |
| --- | --- |
| نقطة الدخول | `openosint <tool> <target> --json` إن وُجد، وإلا استدعاء الدالة المنظّمة (`search_username`/`search_email`/`search_phone`) عبر subprocess بوضع passive فقط |
| المهلات | 180 ثانية كحد أقصى للعملية لأن الدوال الداخلية تصل إلى 180 |
| حدود المعدل | تُفرض على مستوى كل أداة داخلية، لا على OpenOSINT ككل؛ سقف يومي واحد للمنصة |
| آلية الإلغاء | `AbortSignal` على مستوى الطلب + `SIGTERM` لمجموعة العمليات |
| تطبيع المخرجات | تُطبَّع مخرجات الأدوات الفرعية بمحوّلاتها الخاصة، ثم تُمرَّر عبر محوّل OpenOSINT كـ `meta.attribution="via openosint"`، مع إبقاء `source.name` للأداة الأصلية لا لـ OpenOSINT |

### 2.5 Holehe — كشف الحسابات المرتبطة ببريد إلكتروني (Account Enumeration)

> ⚠️ **قسم حسّاس — اقرأ التوصية كاملة قبل أي قرار.**

- **الوظيفة:** يتحقق من تسجيل بريد إلكتروني على مواقع عبر **تدفّقات التسجيل/استعادة كلمة
  المرور**. المصدر نفسه يصف ذلك، و README يصرّح: *"Retrieves information using the forgotten
  password function"* و*"Does not alert the target email"*.
- **الصيانة:** آخر commit **2024-09-10**، وآخر حزمة PyPI `1.61` بتاريخ **2022-07-21**؛
  لا GitHub Release. أي أن المشروع دون تحديثات جوهرية منذ ~26 شهراً، بينما تتحوّل التدفقات
  على المواقع باستمرار → **معدّل فشل صامت مرتفع محتمل** (غير متحقق عملياً).
- **الاعتماديات:** 6 حزم (`termcolor`, `bs4`, `httpx`, `trio`, `tqdm`, `colorama`).
  `requires_python` **غير معلن** في `setup.py`.
- **الشبكة:** كل الوحدات تُشغَّل في `trio.open_nursery` **بلا حدّ تزامن صريح** →
  **123 وحدة**، كل واحدة طلب–طلبين (بحد أقصى 6)، أي **~199 طلباً** و**~138 مضيفاً فريداً**
  في تشغيل واحد كامل. هذا عدّ آلي على الشيفرة و**غير متحقق** على الشبكة.
- **خصوصية وكشف:** استعلامات استعادة كلمة المرور قد تولّد تنبيهات أمنية لدى المستخدم أو
  تنبّه المزوّد، حتى لو لم يُرسَل بريد فعلي. و OpenOSINT نفسه يصنّفها «noisy» ويصفها بأنها
  *"may notify the account owner or trigger security alerts"*.

#### التوصية: ⛔ **لا يُفعَّل كشف الحسابات افتراضياً — أبداً.**

- **افتراضياً:** `account_enumeration = off`، والتكامل غير موجود في قائمة الأدوات المتاحة
  للوكيل/الـ API إطلاقاً.
- **آلية التفعيل:** **feature flag معطّل افتراضياً** (`ENABLE_ACCOUNT_ENUMERATION=false`)،
  لا يُفعَّل إلا **بموافقة صريحة من المستخدم** على مستوى الطلب، مع إقرار صريح بأن الهدف
  يخصّه أو أنه مفوّض قانوناً، ثم موافقة ثانية (double opt-in) قبل التنفيذ.
- **قيود إلزامية عند التفعيل:** بريد واحد لكل طلب، ≤ 10 وحدات/طلب (allow-list ثابتة لا
  القاعدة الكاملة)، مهلة 20 ثانية، وسجل تدقيق (audit log) يربط كل تشغيل بالمستخدم والسبب.
- **البديل المشروع والمفضّل:**
  1. **تحقّق موجّه بالهدف (Verified/Consensual Lookup):** أن يتحقق صاحب البريد بنفسه
     (إرسال رسالة تحقّق، أو OAuth) بدل الاستدلال من تدفقات الغير.
  2. **المصادر الرسمية للانتهاكات:** خدمات مثل HIBP عبر واجهة معتمدة (التحقق يتطلّب
     مفتاحاً وتُسجَّل الاستعلامات)، وهي أدق وأقل عدوانية من تخمين التسجيل.
  3. **معلومات عامة بلا استعلام مباشر:** فحص وجود بريد على نطاق ما عبر سجلات DNS/MX
     أو بيانات عامة، لا عبر تدفق استعادة كلمة المرور.
  4. **الرفض الصريح:** إن لم تتوفر موافقة، **يرفض المحوّل التنفيذ** ويعيد
     `status="skipped"` مع `error="consent_required"`.

**تصميم المحوّل المقترح (Holehe) — لا يُنفَّذ إلا بعد اعتماد الـ flag**

| البند | التصميم |
| --- | --- |
| نقطة الدخول | `holehe <email> --only-used --no-color --no-clear` مع allow-list صغيرة؛ لا استدعاء للمكتبة، ولا تمرير `--csv`/`-T` فقط |
| المهلات | 20 ثانية إجمالية للعملية كاملة (لا يوجد حدّ داخل الأداة فعلياً)، 8 ثوانٍ لكل وحدة |
| حدود المعدل | بريد واحد/طلب، ≤ 10 وحدات، سقف يومي منخفض، وفاصل ≥ 60 ثانية بين التشغيلات |
| آلية الإلغاء | مجموعة عمليات + `SIGTERM` → `SIGKILL`؛ الإلغاء يُعيد `status="skipped"` لا `not_found` |
| تطبيع المخرجات | لكل وحدة: `status=found` (موجود)، `not_found`، `rate_limited` عند `rateLimit=true`، `error` عند `error=true`؛ `evidence` يحمل الحقول المُقنّعة فقط (`emailrecovery`/`phoneNumber` بعد النزع) ولا يُخزَّن البريد الكامل في السجلات |

## 4. قيود معروفة

1. **«مخطط النتيجة الموحّد» في البند 7:** نصّ المهمة المتاح لا يحدّده؛ الاقتراح أعلاه
   استنتاج توثيقي ويحتاج مطابقة قبل التنفيذ.
2. **أعداد الطلبات** أغلبها مقروء من الشيفرة/الإعدادات، لا من التقاط حركة فعلي —
   موسومة **«غير متحقق»** حيث ينطبق.
3. **إصدارات الدعم على كل منصّة** (خصوصاً Holehe مع غياب `requires_python`) **غير متحققة**.
4. **عدد النجوم** لحظةً زمنية واحدة (2026-11-26)؛ يتغيّر.
5. لم يُشغَّل أي من الأدوات فعلياً خلال هذا البحث — التقييم مبني على المصدر والوثائق
   والبيانات الوصفية فقط.

## 5. العمل المتبقي

1. **مطابقة مخطط النتيجة** مع تعريف البند 7 الرسمي (أو تعديله في وثيقة مستقلة).
2. **مراجعة قانونية** لـ GPL-3.0 قبل أي قرار بشأن Holehe/PhoneInfoga (توزيع أو ربط).
3. **قياس فعلي للطلبات** (traffic capture) لـ Sherlock/Maigret/Holehe على مجموعة صغيرة
   من المواقع، وتحويل «غير متحقق» إلى أرقام مقيسة.
4. **اختبار ميداني محدود** لـ Sherlock على allow-list، لقياس نسبة `WAF`/`Unknown` الحقيقية.
5. **إعادة تقييم Holehe**: هل بقيت التدفقات تعمل بعد ~26 شهراً دون تحديث؟ ثم تحديث
   البديل المشروع إن ثبت تعطّلها.
6. **لا يُضاف أي adapter** حتى استكمال 1–4 واعتماد النتائج.
